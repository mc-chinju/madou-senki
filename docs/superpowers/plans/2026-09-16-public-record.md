# 捨て札の非公開化と戦記（公開アクションログ）の全件閲覧 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This document is a planning deliverable; it does not authorize production deploy by itself.

**Goal:** 「その場で見えたものは戦記で見返せる。誰も見ていないものは見えない」にそろえる。捨て札は枚数だけを公開し、中身は他者へ送らない。表向きに出た札・判定・ダメージ・パスなどは、対戦開始から全件を戦記で確認できる。

**Architecture:** 公開の線は「その時点で表向きに場へ出たか」で決め、記録はその時点の内容で固定する。エンジンが公開事実を構造化イベントとして記録し、既存の `logView` の許可リストで視点ごとに投影する。捨て札の中身は `viewFor` の段階で落とす（画面で隠すだけにしない）。

**Spec:** 本計画。根拠はユーザー判断（2026-09-16「捨て札は基本クローズ。自分の捨て札は見られるようにしつつ、ログは全件見たい。細かいところは後でもよい」）、[オンライン設計 §8](../specs/2026-09-07-online-game-design.md)（秘密情報と画面）、[G11](../../rules/second-edition/rulings.md)（回収と秘密情報）。

**Worktree / ブランチ:** 実装開始時に専用ブランチを切る。main への merge はユーザーが行う。[初期配置の同時化](2026-09-16-concurrent-ready.md) とは独立に進められる。パスの記録だけは、先に入った側に合わせる。

## 段階

- **第1段（この計画で実装する）:** 捨て札の中身を他者へ送らない。戦記に主要な公開事実を足し、全件を見られるようにする
- **第2段（後回し。下の「後段」に設計だけ残す）:** 自分の捨て札一覧、伏せたまま捨てた枚数の記録、戦記の絞り込み、過去分のページ取得、決着後の全公開

第1段では、自分の捨て札も含めて画面は枚数だけになる。自分が表向きで使った札は戦記で見返せる。

## 現状

捨て札:

- `PlayerView.discard: string[]` で中身を全員へ送っている（`packages/engine/src/view.ts`）。画面は `Board.tsx` の見出しに枚数だけを出すが、通信内容からは他者が伏せて捨てた札（手札調整、死亡時の手札・伏せた詠唱・裏向き従者など）が読める。§8「全状態を送り CSS で隠す方式は使わない」に反する
- `GameState.discard` は札IDの配列だけで、誰が・表向きで捨てたかを持たない。捨て札へ積む処理は `packages/engine/src` の10ファイル・14か所に散らばっている
- web の画面は `view.discard.length` 以外を使っていない。worker の試験の多くは保存済み状態の `state.game.discard` を読んでおり、投影の変更の影響は受けない

戦記:

- `GameState.events` のうち `audience==='public'` を `logView` で投影し、`PlayerView.logs` として毎回全件送る。画面 `PublicLog.tsx` は末尾30件だけを出す
- 記録されるのは配役・ドロー・OPEN・初期配置・正体公開・死亡/復活/流浪・陣営変更・祈願・贈与・獣捕獲など、主に lifecycle 系だけ。`appendEvent` の呼び出しは `combat/attack.ts` と `turns.ts` に各1か所、判定（`rolls/`）・回収（`reclaim.ts`）・捨て札（`discard.ts`）には0か所
- そのため、攻撃・防御・間合い/踏み込み・いつでもカード・能力・出目・ダメージ・距離・詠唱・休息・手番・パス・回収が戦記に残らない

## 公開範囲

| 場面 | 全員の戦記 | 本人の戦記 | 段階 |
|---|---|---|---|
| 手番の開始/終了、休息 | 記録 | 同じ | 1 |
| 表向きで使った札（攻撃・防御・反撃・間合い・踏み込み・いつでも・手番カード） | 札名、使用者、対象 | 同じ | 1 |
| 能力の宣言・取消 | 能力名、使用者、対象 | 同じ | 1 |
| 判定 | 種類、出目、目標値、成否、振り直し | 同じ | 1 |
| ダメージの適用、状態の付与/回復 | 値 | 同じ | 1 |
| 距離の変化 | 誰と誰が近/遠になったか | 同じ | 1 |
| パス | 誰がどの窓でパスしたか | 同じ | 1 |
| OPEN、正体公開、死亡、復活、流浪、陣営変更 | 既存どおり | 既存どおり | 既存 |
| 表になった従者（防御・破壊・死亡）、士気判定 | 従者名、結果 | 同じ | 2 |
| 詠唱・従者の配置・並べ替え | 事実と枚数（札は伏せる） | 札名 | 2 |
| 伏せたまま捨てた札（手札調整、死亡時の手札・伏せた詠唱・裏向き従者、命中時の詠唱破棄） | 枚数 | 札名 | 2 |
| 回収 | 札名（表向きで使われた札のため）。回収権の有無は G11 どおり伏せる | 同じ | 2 |
| 捨て札を山札に戻す（大陸の夜明け、山札切れ） | 事実 | 同じ | 2 |
| ドロー・補充 | 枚数（既存） | 札名（既存） | 既存 |
| 覗き見・祈願・贈与など本人だけに見せる効果 | 既存の audience のまま | 既存のまま | 既存 |

原則:

- 記録はその時点の内容で固定する。あとで裏向きの従者が表になっても、過去の配置記録に札名を書き足さない
- 他者が戦記から、表向きで使われた札の多くを数えられるのは許容する（卓上で見て覚えているのと同じ）。伏せたまま捨てた札は誰にも分からない
- 捨て札の枚数・手札の枚数・山札の枚数は公開のまま

## 第1段の設計

捨て札の投影:

- `PlayerView.discard: string[]` を `discardCount: number` に替える
- 見出しは「捨て札 N」のまま

イベント（エンジン）:

- `GameEvent.type` に次を足す: `TURN_STARTED`、`TURN_ENDED`、`REST`、`CARD_PLAYED`（`use`: attack / defense / counter / maai / advance / anytime / turn）、`ABILITY_DECLARED`、`ABILITY_CANCELED`、`ROLL_RESOLVED`、`DAMAGE_APPLIED`、`STATUS_CHANGED`、`DISTANCE_CHANGED`、`PASSED`
- `GameEvent` に公開用のフィールド `targetIds`、`use`、`abilityId`、`roll`（`kind`・`faces`・`total`・`threshold`・`success`・`attempt`）、`amount`、`windowKind`、`turnNumber` を足す。文章はエンジンで作らず、画面が組み立てる
- 記録はできるだけ状態を確定させる関数（判定の確定、ダメージの適用、距離の更新、手番の切り替え）で行い、コマンドの入口ごとに書く箇所を減らす
- `CARD_PLAYED` はカードが表向きで解決領域・場に出た時点で記録する。伏せる詠唱・配置は第1段では記録しない
- `logView` の許可リスト方式は維持し、新しい種類ごとに出してよいフィールドを明示する

転送:

- 第1段は今の全件送信のままにする。Task 1 で1試合分の大きさを測り、目安（1試合の公開ログが100KB、または1回のスナップショットが200KB）を超えたら第2段のページ取得を前倒しする

画面:

- `PublicLog.tsx` を全件スクロールにし、手番ごとに見出し（「3手番 Bさん」）で区切る
- 最新へ自動追従し、上へスクロールしたら追従を止めて「最新へ」ボタンを出す
- 同じ窓で続いたパスは「B・C・D がパス」と1行にまとめる
- 新しい種類ごとに文言を作る。未知の種類は種類名を出さず「記録」と出す

## 後段（設計メモ）

第1段が入ってから、必要に応じて別計画にする。

- **自分の捨て札一覧:** 捨て札へ積む14か所を `discardPhysical` 相当の1関数にまとめ、札ごとに「捨てた人」「表向きだったか」を持つ。自分の視点には、自分が捨てて今も捨て札に残っている札を出す。山札へ戻したら消える。見出しの枚数をボタンにしてダイアログで出す
- **伏せた札の記録:** 上の関数で、伏せたまま捨てた札を全員には枚数、本人には札名で記録する。詠唱・従者の配置・並べ替え、表になった従者・士気判定、回収、山札へ戻す処理も記録する
- **戦記の絞り込み:** 全員 / 自分に関係する記録 / 参加者別
- **過去分のページ取得:** `PlayerView.logs` を最新50件にし、過去分は WebSocket の `LOG_PAGE { beforeId, limit }` で視点ごとに投影して返す
- **決着後の全公開:** 結果画面で全員の正体・手札・捨て札を開示するか。感想戦用で、別途判断する

## リスク

- 記録漏れ: 状態を変える経路が多い。確定処理の関数で記録し、Task 3 の全試合試験に「解決領域へ出た札に `CARD_PLAYED` がない」検出を足す
- 秘密漏れ: 許可リストを広げすぎると漏れる。種類ごとに許可フィールドを試験で固定する
- 戦記の長さ: パスと判定を全部出すと長い。表示でまとめ、データは細かく残す
- 送信量: 全件送信のまま戦記が増える。Task 1・7 で測り、目安を超えたらページ取得を前倒しする
- 既存の卓: 変更前に始まった卓には過去の記録がなく、変更以降の記録だけが出る

## 計測記録

`node --experimental-transform-types --no-warnings --import ./scripts/ts-resolve-hook.mjs scripts/measure_public_record.ts`（bot 全試合。bot-full-game.test.ts と同じ種）。目安は公開ログ 100KB、1回のスナップショット 200KB。

| 時点 | 席数 | 手数 | 公開イベント数 | 公開ログ (bytes) | 最終スナップショット (bytes) | 最大スナップショット (bytes) |
|---|---|---|---|---|---|---|
| 変更前 | 4 | 430 | 14 | 1,151 | 8,322 | 9,978 |
| 変更前 | 10 | 901 | 27 | 2,037 | 13,294 | 15,006 |
| 第1段後 | 4 | 430 | 409 | 33,884 | 40,753 | 41,728 |
| 第1段後 | 10 | 901 | 865 | 70,738 | 81,754 | 81,754 |

bot の試合では目安を超えない。ただし公開イベントの大半はパス（10席で865件中約800件）で、bot の10席の試合は攻撃が8回しかない。攻撃1回あたり10席でおよそ8KB増えるため、攻撃が十数回を超える実戦では公開ログが100KBを超える見込みが高い。ページ取得の前倒しは第1段の範囲外とし、後段で判断する。

## 実装で決めたこと（第1段）

- 状態の付与/回復（`STATUS_CHANGED`）と距離の変化（`DISTANCE_CHANGED`）は、生成箇所が多いため `transition()` の最後に確定前後の状態を比べて1か所で記録する（`public-record.ts` の `recordStepChanges`）。手番終了（`TURN_ENDED`）も手番の席が変わったときに同じ場所で記録する。死亡・流浪で外れた参加者の状態の消滅と距離の変化は記録しない
- `turnNumber` は表示用の1始まりの通し番号（`GameState.turnNumber + 1`）
- 判定は振るたびに `ROLL_RESOLVED` を記録する。振り直しは同じ `rollId` で `attempt` が増える。振った後の命運凶変は `forcedFailure` を付けて同じ試行をもう一度記録する
- 未公開の正体の参加者の能力の宣言・取消と、その参加者が振った判定は `concealed` を持ち、本人以外には能力名・対象・目標値・成否を送らない（既存の `projectRoll` と画面の現在の行動と同じ線）
- 回収の窓のパスは記録しない（回収権の有無は G11 どおり伏せる）。回収権を使う能力（reuse）の宣言も記録しない
- `DAMAGE_APPLIED` は `settleDamage` でダメージが加わったときだけ記録する（1回の攻撃の複数ヒットは対象ごとの合計1件）。休息・薬・能力による回復は、使ったカードや判定の記録で追う
- 破壊・死亡で解決領域を通る従者は第2段で記録するため、第1段の `CARD_PLAYED` の対象外
- ブラウザ試験の捨て札の中身の確認は、通信内容ではなく `/__test/rooms/:id/game` の保存済み状態を読む `storedDiscard()` に替えた
- bot は優先順で合法手のある席を探し、その席の投影を再利用する。主な遷移では公開イベントの履歴を入れ子も含めて独立にコピーし、全件の再シリアライズを避ける。bot・worker の既存試験の時間上限は変更しない
- 計測スクリプトは依存を足さず、Node の型除去と `scripts/ts-resolve-hook.mjs` で実行する
- 通し確認（Task 7）は `tests/e2e/public-record.spec.ts` で行う。bot の4人対戦を WebSocket で最後まで進め、40手ごとに保存済み状態と2席目の最新スナップショットを突き合わせ（捨て札の中身・他者の手札・伏せた札・未公開の正体のIDがない、`discardCount` が一致）、決着後に2席目の画面で「1手番」までさかのぼって攻撃札・出目・ダメージ・パスの行を確認する
