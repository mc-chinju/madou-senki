## Task L1: 誰が誰に何をしたかを戦記から読めるようにする

いまの戦記は、攻撃を「〈札名〉を攻撃に使いました（対象: ◯さん）」の1行で表す。札を使わない攻撃（従者攻撃・仮想従者・全軍突撃）は `cardInstanceId` が無く「カードを攻撃に使いました」になる。破壊された従者などは札名が文字列のままで、詳細を開けない。

- [x] 攻撃の宣言を「◯さんへ攻撃を宣言しました（〈札名〉）」の形にする。対象が複数ならすべて出す。踏み込み・間合い・防御・反撃も、相手が居る行動は相手を出す
- [x] 札を使わない攻撃を記録する: 従者攻撃は従者の札名（表になっているので公開）、仮想従者は能力名（`ABILITY_DECLARED` の公開規則に従う）、全軍突撃は使った札と従者
- [x] 戦記に出る札名・人物名・能力名はすべて詳細を開けるリンクにする（`CardLink` / `AbilityLink` を使う）。素のテキストで札名を出している箇所（`FOLLOWER_DESTROYED` など）を直す
- [x] 試験: 全イベント種類を1件ずつ描画し、札名・人物名・能力名が素のテキストで出ていないことを固定する。従者攻撃・仮想従者・全軍突撃の行
- コミット: `feat: name the target and the card in every public record line`

実装で分かったこと（2026-09-19）: 札を使わない攻撃のうち、記録が無かったのは仮想従者だけだった。従者攻撃は `follower-bundles.ts` が従者札を `CARD_PLAYED` で、全軍突撃は `all-army.ts` が全軍突撃せよと従者札の2枚を既に記録している。仮想従者のために `ATTACK_DECLARED`（能力名と対象。能力名は `ABILITY_DECLARED` と同じ公開規則）を足した。

## Task L2: 判定の見え方をそろえ、判定不要も記録する

いまは、正体を公開していない席の判定は、目標値も成否も他者に出ない（`view.ts` の `logView`、`rolls/advance.ts` の `projectRoll`）。卓上では出目も成否も全員が見るので、成否は公開に寄せる。目標値（精神力の値）は人物の能力値そのものなので伏せたままにする。

- [x] 裁定: G03 の隣に「判定の公開範囲」を足す。出目・合計・振り直し・成否・強制失敗は全員に見せ、目標値と修正の内訳は正体を公開している席だけに見せる。オンライン補完であることを明記する
- [x] `logView` と `projectRoll` の両方を同じ規則にする（戦記と判定パネルで食い違わせない）
- [x] 判定が要らなかった場合を記録する（`CHECK_SKIPPED`）。使用レベルが足りていて判定不要だった場合と、能力・カードで判定を免れた場合を区別する
  - 能力が理由なら、その席が正体を公開していれば能力名を出し、公開していなければ `concealed` にして「特殊能力で判定を免れました」とだけ出す（`recordAbility` と同じ扱い）
  - 判定が要るかどうかは卓上でも見えるので、事実そのものは全員に出す
- [x] 試験: 未公開の席の判定で、成否は出るが目標値は出ない。公開済みなら両方出る。判定不要・能力による免除の記録が公開・非公開それぞれで正しい。`public-record-privacy.test.ts` が通る
- [x] 画面: 判定の行を「〈目的〉で 3・5（合計8、目標値9・失敗）」のように読める形にする。目標値が見えない席では「（成功）」だけにする
- コミット: `feat: show every roll result and record skipped checks`

実装で分かったこと（2026-09-19）: `CHECK_SKIPPED` の理由は `level` / `ability` / `card` の3つにした。「能力・カードで免れた」を1つにまとめると、能力名を伏せた席で「特殊能力で判定を免れました」と出してしまい、カードの記述で判定不要だった場合と区別できなくなるため。記録は `attack.ts` の `continueAction` が効果Lv窓へ進む1か所（判定を1度も振らなかったときだけ）で行い、宣言窓が開き直しても二重に記録しない。

## Task L3: 表示順と読み方

既定は今のまま「古いものが上、新しいものが下」にする。攻撃 → 判定 → ダメージが起きた順に続けて読めること、既に自動追従と「最新へ」があることが理由。走り読み用に切り替えを足す。

- [x] 「新しい順 / 古い順」の切り替えを足す。新しい順では手番見出しも逆順にし、手番の中も新しい順にする。選択は同じ卓の再読み込みで保つ
- [x] 新しい順のときは自動追従を先頭方向にする（新着が上に積まれる）。「最新へ」は先頭へ戻る
- [x] `apps/web/test` に順序の試験（見出しと行、パスのまとめが逆順でも壊れない）
- コミット: `feat: let the reader flip the public record order`

実装で分かったこと（2026-09-19）: 並べ替えは `publicLogSections(view, order)` の最後で行う。パスのまとめは隣り合う記録を見るので、まとめ終えてから節と行を反転する。手番見出しは節の見出しなので位置は変わらず、節の並びと節内の行だけが逆になる。新しい順では番号が古い行から数えるよう `<ol reversed start=…>` にする。選択は `sessionStorage` に卓のパスごとに保存する。
