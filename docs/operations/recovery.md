# 卓と通信の復旧

正本は各卓のDurable Object SQLite。D1の卓一覧から試合状態を再構成しない。切断はパス・敗北・退席・卓主移譲を意味しない。

## プレイヤーの復帰

着席したアカウントでログインした状態で卓URLを開く。接続は本人の席を照会し、保存済みの個人別スナップショットへ同期してから操作を有効にする。別タブを開いた場合は新しいタブが操作可能になり、古いタブは閲覧のみになる。

ACKを受け取る前に切断・再読込した場合、sessionStorageに残した同じコマンド本文・IDを再送する。サーバーは保存済みの受理記録を返すので、乱数やカード消費をやり直さない。古いrevisionや窓に対する新規操作は拒否し、最新の状態を再表示する。

Cookie削除・期限切れ・別端末では、同じメールアドレスの確認コードかパスキーでログインし直せば同じ席へ戻れる。表示名や招待リンクは本人確認にならない。2026-09-15のアカウント導入前にゲストCookieで着席した卓は復帰できない。トラブル時にCookie・確認コード・トークンをチャットへ貼らない。

## 障害の切り分け

| 症状 | 確認と挙動 |
|---|---|
| 接続中・再接続中のまま | 通信復旧後に同じ卓を開く。操作待ちを保存しており自動で進めない |
| あるタブだけ操作不可 | 同じブラウザの新しいタブが操作権を持っていないか確認 |
| 卓一覧が古い | 卓DOの状態は維持され、Outboxをalarmで再送する。D1の反映遅延を試合の消失と扱わない |
| 操作結果が不明 | 同じタブから再接続。新しいIDで同じ操作を作り直して補償しない |
| 準備済みでも開始できない | `RULESET_NOT_READY`なら未実装効果の検査。現行試作では正常な拒否 |
| 全員が終了したい | 卓管理から全員で閉卓へ同意する。状態を保存し、勝者を勝手に決めない |
| 非互換版の卓 | 保存内容を消さず、該当版のコード・設定を復旧する。新規試合として上書きしない |

## 運用側の確認

HTTPエラーは固定コードのみを返す。ログや問い合わせへ秘密の手札、山札、正体、セッションCookie、招待トークンを含めない。公開卓ID、時刻、エラーコード、ブラウザの接続表示でまず切り分ける。

DOではスナップショット、イベント、コマンド受理、Outboxを同一トランザクションへ保存する。保存前の失敗は未受理、保存後ACK前の失敗は再送で同じACKへ戻る。D1の投影はrevisionが新しいものだけ適用する。管理者がD1の席数や試合状態を書き換えて復旧しようとしない。

ローカルではSQLiteのロールバック、再送、eviction後の復元、D1障害と再送、割り込み・乱数・従者境界の復元を実Workerテストで検査済み。実Cloudflareでの休止復帰、バックアップ復元、再デプロイ中の継続はまだ実施していない。

## 配備の失敗とルール版

まず問題の卓のoriginを配備記録のWorker・rulesetId・D1・ROOMSへ対応させる。別版のWorkerへ卓を移して復旧しない。非互換更新の分離と旧版保持は[配備手順](deploy.md#非互換なルール版の切り替え)に従う。

同じルール版のコードを戻す場合も、保存schemaと配備後の状態を旧成果物が読めることを確認してから、その版のWorkerだけを対象にする。互換性が不明なら旧コードへの切り戻しは保留し、保存内容を維持して該当版を修正する。コードの切り戻しをDO・D1の巻き戻しと扱わず、受理済みコマンドを消したり別IDで再実行したりしない。復帰時は同じorigin・Cookieで再接続し、本人向けsnapshot、revision、未ACKの同一ID再送を確認する。

### 勇気の受取人選択を保存した旧形式

`beneficiary-choice` にある回収判断で `responseResume` がない形式は、受取人の辞退後に戻る参加者順・位置を保存していない。現行形式は判定前の参加者・カーソル・回答済み席を保持するが、旧形式の自動移行は実装されていない。同じ `schemaVersion` / `rulesetId` であることだけで互換と判断しない。

現在の生存者や席順から回答順を作り直したり、全員回答済みとして窓を閉じたりしない。旧卓のDOを新版へコピーせず、元の版のリソースを保持する。既に異なる版で開いた場合も保存内容と受理記録を保全し、元の応答順を含む保存資料があるか確認する。その資料がない状態を「移行済み」「正常復帰」と報告しない。調査記録（`ledger-accepted-2026-09-15:docs/operations/evidence/2026-09-10-legacy-beneficiary-resume.md`）。
